# College Portal — практические №2 и №3

Учебный портал на Next.js App Router и TypeScript: публичные страницы, курсы и кабинет студента. Оформление намеренно простое, без внешних шрифтов и декоративной графики.

## Запуск

Из корня репозитория:

```bash
cd college-portal
npm ci
npm run dev
```

Нужен Node.js 20.9 или новее. Откройте http://localhost:3000.

```bash
npm run lint
npm run build
npm run typecheck
```

Для production после сборки: `npm start`. Все команды выполняются в папке `college-portal`. В корне репозитория находится отдельная предыдущая работа, агрегатор статей.

## Практическая №3

| Задача | Реализация |
| --- | --- |
| Активная навигация | Клиентский `src/components/PortalNav.tsx`, хук `usePathname` |
| Выделение пункта | `aria-current="page"`, `fontWeight: 'bold'`, фон и рамка; вложенные страницы также выделяют свой раздел |
| Серверный layout портала | `src/app/(portal)/layout.tsx` без директивы `'use client'` |
| Фильтр `all / lecture / practice` | Клиентский `CourseFilter`, `useSearchParams`, `useRouter` и `usePathname` |
| Серверная фильтрация | `CoursesPage` читает `await searchParams` и фильтрует исходные курсы |
| Suspense | Фильтр находится внутри `<Suspense>` |
| Сохранение фильтра | Значение берётся из URL; работают прямые ссылки, перезагрузка и история браузера |
| Защита кабинета | `src/proxy.ts`, matcher `/portal/:path*`, cookie `student_pin` |
| Возврат после входа | Редирект `/login?redirect=...` сохраняет путь и строку запроса |

При выборе «Все» параметр `type` удаляется. Остальные параметры URL сохраняются. Неизвестное значение типа считается `all`; при повторяющемся параметре используется первое значение на сервере и клиенте.

В `PortalNav` путь сопоставляется по границе сегмента: `/portal/grades/details` относится к «Оценкам», а `/portal/grades-other` — нет.

## Учебный вход и выход

Откройте `/portal/grades` без cookie: proxy перенаправит на `/login?redirect=%2Fportal%2Fgrades`. Введите любой непустой учебный PIN. Форма установит `student_pin` на час и выполнит `router.replace` на исходную страницу. Кнопка «Выйти» удаляет cookie и возвращает на вход.

Можно проверить условие из лекции вручную в консоли браузера:

```js
document.cookie = 'student_pin=test; Path=/';
```

После этого откройте `/portal/schedule`. Для удаления:

```js
document.cookie = 'student_pin=; Path=/; Max-Age=0';
```

Это именно проверка наличия непустой cookie, предусмотренная заданием. PIN не сверяется с базой и не подтверждает личность; данные кабинета демонстрационные. Для настоящей авторизации понадобятся проверяемые серверные сессии и проверка доступа рядом с данными.

Параметр `redirect` разрешает только внутренние адреса `/portal` и `/portal/...`; внешний или некорректный адрес заменяется на `/portal/dashboard`.

## Что сохранено из практической №2

- Группы маршрутов `(public)` и `(portal)` и их отдельные серверные layouts.
- Публичные `/`, `/about`, `/courses` и `/login`.
- Кабинет: `/portal/dashboard`, `/portal/grades`, `/portal/schedule`; `/portal` ведёт в обзор.
- Данные трёх курсов в `src/data/courses.ts`.
- Динамические `/courses/[id]`, асинхронный `params`, `generateStaticParams()` для id 1, 2, 3.
- `notFound()` и отдельная страница отсутствующего курса.

## Проверка вручную

1. Откройте `/courses?type=practice`: выбран пункт «Практика», в списке только «Практикум по React».
2. Переключите на «Лекции»: URL содержит `type=lecture`, показаны два курса. Обновите страницу и проверьте кнопки браузера «Назад» и «Вперёд».
3. Без cookie откройте `/portal/schedule?week=2`: откроется форма входа с сохранённым адресом. После входа вернёт в расписание вместе с `week=2`.
4. Переключайтесь по меню кабинета: только текущий пункт имеет жирный шрифт, фон и рамку.
5. Нажмите «Выйти», затем снова откройте кабинет: доступ снова требует cookie.
6. Откройте `/courses/999`: будет ответ 404. После сборки курсы 1, 2 и 3 остаются предварительно сгенерированными.

## Упрощение оформления

`src/app/globals.css` занимает 3 759 байт вместо исходных 13 118 (примерно на 71% меньше). Простое оформление сохраняет размеры заголовков, читаемые отступы, границы блоков и таблиц, заметную активную навигацию и адаптацию для телефона. Внешних шрифтов, анимаций, теней и декоративной графики нет.

Next.js и eslint-config-next обновлены с 16.4.0 до 16.4.6 для исправления обнаруженных уязвимостей. `package-lock.json` фиксирует зависимости этого проекта. API-ключи и `.env` не требуются.

## Сверка с исходным заданием

Приложенный файл «3. Маршрутизация и файловая структура.md» заканчивается задачей 3. В разделе практического задания перечислены ровно три задачи; API-эндпоинты и специальные файлы до него приведены как материал лекции.

1. **Активное меню:** откройте кабинет, перейдите между «Обзором», «Оценками» и «Расписанием». Текущий пункт выделяется; layout остаётся серверным.
2. **Фильтр:** откройте `/courses?type=practice`, обновите страницу. Выбрана практика и показан один курс; список фильтруется на сервере.
3. **Proxy:** удалите `student_pin` и откройте `/portal/grades?term=2`. Ответ перенаправляет на `/login?redirect=%2Fportal%2Fgrades%3Fterm%3D2`; после учебного входа возвращает к оценкам.
