# Проверка практической №3

Проверено 10 ноября 2026 года на production-сборке `college-portal`.

## Команды

- `npm run build` — успешно, proxy обнаружен; курсы 1, 2 и 3 предварительно сгенерированы.
- `npm run lint` — без ошибок.
- `npm run typecheck` — без ошибок.
- `npm audit --omit=dev` — уязвимостей не найдено после обновления Next.js до 16.4.6.
- `git diff --check` — без ошибок форматирования.

## HTTP и браузер

- Публичные страницы открываются без cookie.
- `/portal`, обзор, оценки, расписание и вложенный URL без cookie возвращают редирект на вход.
- `redirect` сохраняет исходный путь и параметры запроса.
- С непустой `student_pin` страницы кабинета открываются; пустая cookie не пропускается.
- Проверка proxy ограничена сегментом `/portal`: похожее имя `/portal-similar` не перенаправляется на вход.
- В каталоге показаны 3 курса для `all`, 2 для `lecture`, 1 для `practice`.
- Прямая ссылка с фильтром, перезагрузка и история браузера сохраняют правильные список и выбранный пункт.
- Переключение типа сохраняет другие параметры URL. Неизвестный тип даёт все курсы; повторяющийся параметр обрабатывается одинаково сервером и клиентом.
- Фильтрация серверная: правильный список и выбранный фильтр присутствуют даже без JavaScript.
- После учебного входа cookie устанавливается, а пользователь возвращается к запрошенной странице вместе с её параметрами.
- Активный пункт меню имеет `aria-current="page"`, жирный шрифт и фон; выделение меняется при навигации.
- После выхода cookie удаляется и новое открытие кабинета снова ведёт на вход.
- Внешний адрес в `redirect` заменяется внутренней страницей обзора.
- На ширине 390 px каталог, оценки, расписание и страница курса не создают горизонтальную прокрутку документа.
- Курсы 1, 2 и 3 открываются, отсутствующий курс возвращает 404.
- В проверенных сценариях нет необработанных ошибок JavaScript.

Layout `(portal)` остаётся серверным, `CourseFilter` обёрнут в Suspense. Учебный вход проверяет только наличие cookie, как предусмотрено заданием.
