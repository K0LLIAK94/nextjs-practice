# Практическая работа: введение в Next.js

«Лист» — агрегатор статей, реализованный на Next.js App Router и TypeScript по заданию из файла «1. Введение в Next.md». Стили написаны на обычном CSS, без Tailwind.

## Запуск

Понадобятся Node.js 20.9 или новее и интернет для установки зависимостей и получения статей. Рекомендуется Node.js 24 LTS.

Распакуйте архив, откройте терминал в папке `next-articles` и выполните:

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. Если порт занят, используйте `npm run dev -- --port 3001`.

Для запуска production-версии:

```bash
npm run build
npm start
```

Проверки кода:

```bash
npm run lint
npm run typecheck
```

Архив содержит исходники и `package-lock.json`. Результаты проверок приведены в `VERIFICATION.md`, скриншоты — в `screenshots/`. Зависимости `node_modules` и результат сборки `.next` не включены: они создаются приведёнными командами. API-ключи и настройка `.env` не нужны.

## Выполнение требований

| Требование | Реализация |
| --- | --- |
| Главная `/`: заголовок, описание, ссылка на каталог | `src/app/page.tsx` |
| Статические title и description главной | Экспорт `metadata` в `src/app/page.tsx` |
| Список `/articles`: 15 статей с сервера | Асинхронный `src/app/articles/page.tsx`, функция `getArticles()` |
| Точный адрес API списка | `https://jsonplaceholder.typicode.com/posts?_limit=15` |
| Названия и ссылки на отдельные статьи | Компоненты `Link` в списке карточек |
| Состояние загрузки | `src/app/articles/loading.tsx` |
| Обработка ошибки и повторная попытка | `src/app/articles/error.tsx` |
| Отдельная статья `/articles/[id]` | `src/app/articles/[id]/page.tsx` |
| Загрузка статьи по id | `https://jsonplaceholder.typicode.com/posts/{id}` |
| Динамический title равен названию статьи | `generateMetadata()` без добавления названия сайта к title |
| Несуществующая статья → not-found | `notFound()` для ответа API 404 и некорректного id |
| Кнопка «Назад к списку», клиентский компонент | `src/components/BackToArticles.tsx`, `'use client'`, `useRouter()` |
| Общая навигация через Link | `src/app/layout.tsx` |

## Как работает перенос SPA

В исходном SPA браузер сначала получал HTML без статей, а после запуска JavaScript загружал данные через `useEffect` и сохранял их в `useState`.

Здесь `ArticlesPage` — асинхронный серверный компонент. Он ожидает `getArticles()` и возвращает разметку с данными. Маршруты статей используют `dynamic = 'force-dynamic'`, а запросы — `cache: 'no-store'`: страницы формируются при запросе (SSR), и сборка не зависит от доступности API. При потоковой передаче сначала может прийти состояние `loading.tsx`, затем готовый HTML статей; сам текст не зависит от клиентского запроса к API.

Главная не загружает изменяющиеся данные и может быть подготовлена статически при сборке. Серверные компоненты и SSR — разные понятия: выполнение компонента на сервере само по себе не означает рендер при каждом запросе.

Данные и их проверка вынесены в модуль с `import 'server-only'`. Метаданные и страница отдельной статьи используют общую функцию `getArticle`, обёрнутую в React `cache`: повторные обращения в рамках одного рендера используют общий результат, без постоянного хранения между запросами.

В актуальном Next.js `params` асинхронны: используется `params: Promise<{ id: string }>` и `await params`. В учебном файле приведён синхронный вариант из более ранних версий.

Клиентскими являются только кнопка возврата и обработчик ошибок. Возврат использует `router.push('/articles')`, чтобы даже после прямого открытия статьи пользователь попадал именно в каталог. При повторной попытке обработчик ошибки обновляет серверные данные и сбрасывает границу ошибки. Ответ 404 считается отсутствующей статьёй, а другие сбои API показывают экран ошибки. В production техническое сообщение серверной ошибки не выводится пользователю.

JSONPlaceholder возвращает учебные тексты на английском; они отображаются без выдуманных переводов. Реальной базы данных, регистрации и редактирования статей в задании нет.

## Самостоятельная проверка

1. Откройте `/`: должны быть заголовок, описание и ссылка на каталог.
2. Перейдите на `/articles`: должно быть 15 карточек. Откройте любую статью.
3. На `/articles/1` проверьте полный текст и заголовок вкладки: он равен названию статьи.
4. Нажмите «Назад к списку»: откроется `/articles`.
5. Откройте `/articles/999999`, `/articles/abc` и `/unknown`: появится страница 404.
6. Откройте исходный HTML ответа `/articles`: он содержит названия и ссылки на статьи, полученные сервером. При потоковой передаче `loading.tsx` React может использовать JavaScript для раскрытия готовой разметки; проверяйте наличие данных в HTML, а не только вид страницы с отключённым JavaScript. Кнопка возврата также требует JavaScript.
7. Чтобы увидеть загрузку, включите ограничение скорости сети в DevTools и перейдите в каталог.
8. Для проверки ошибки ограничьте доступ к JSONPlaceholder именно у процесса Node.js, затем обновите каталог. Отключение интернета только в DevTools не блокирует серверный fetch. После восстановления доступа нажмите «Попробовать снова».
